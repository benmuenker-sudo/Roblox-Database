# Live-Ops, Events und Updates

> Stand: 2026-10-24 · Gesamt-Vertrauen: 🟡 (Beobachtung bei Top-Spielen), 🧠 für Planung

## Kurzfassung
Die Top-Spiele sind **Live-Spiele**: Sie bekommen regelmäßig Updates und zeitlich begrenzte Events, die Spieler zurückholen und Clips erzeugen. Der „Update → Event → Hype"-Zyklus prägt Roblox-Hits. 🟡 Gefahr: Wenn Events die *einzige* Retention sind, bricht die Aktivität dazwischen ein. Baue Systemtiefe darunter.

## Arten von Live-Ops
| Art | Dauer | Zweck | Beispiel |
|---|---|---|---|
| **Mini-Event** | Stunden–1 Tag | Aufmerksamkeit, Clips | Doppelte Drops, Boss-Spawn |
| **Wochen-Event** | 3–7 Tage | Rückkehr | Themen-Woche mit Sonder-Item |
| **Saison** | 4–8 Wochen | Langzeitbindung | Saisonpass, Rangliste |
| **Großes Update** | Alle 2–6 Wochen | Neue Zone/Mechanik | Neue Mechanik, neuer Stil |
| **Feiertag/Anlass** | Jahreszeit | Stimmung | Halloween, Winter |
| **Community-Event** | variabel | Bindung | Server-Ziel, Wettbewerb |
| **Admin/Sonderevent** | kurz | Spektakel, Clips | Außergewöhnliche Spawns (bei Hits beobachtet 🟠) |

## Gestaltung guter Events
1. **Ein Grund:** Event hat ein klares Thema und Ziel.
2. **Zeit begrenzt:** Ja, aber ohne Manipulation (ehrliche Dauer anzeigen).
3. **Für alle erreichbar:** Nicht nur Zahlende profitieren.
4. **Sichtbar:** In der Spielwelt (Dekoration, Ton, Banner) und im UI.
5. **Teilbar:** Schöne Momente für Screenshots/Clips.
6. **Messbar:** Kennzahlen vorher/nachher (Spieler, D1, Umsatz, Spielzeit).
7. **Nachlauf:** Nach dem Event bleibt etwas (Titel, Item, Neuerung).

## Updates planen
- **Pipeline:** Arbeite 2–3 Updates voraus, sonst läufst du hinterher.
- **Testen:** Intern/Test-Server vor Live (Roblox bietet Teststrukturen im Creator Hub).
- **Kommunikation:** Update-Notes im Spiel, Community-Kanal (Discord/Gruppe).
- **Rollback-Plan:** Fehler passieren. Halte letzte stabile Version bereit.
- **Update-Fenster:** Außerhalb der Stoßzeiten deployen; Spieler warnen.

## Event-Fallen
| Falle | Folge | Besser |
|---|---|---|
| Events ersetzen Systemtiefe | Aktivität bricht ein | Meta-Systeme stärken |
| Zu viele Events | Ermüdung, Entwickler-Burnout | Rhythmus festlegen |
| Exklusiv nur für Käufer | Frust, schlechter Ruf | Verdienbare Wege |
| Fake-Knappheit | Vertrauensverlust, Regelrisiko | Ehrliche Fristen |
| Bugs im Event | Schaden an Reputation | Testen, Rollback |

## Kennzahlen für Events
- Spieler (CCU) vor / während / nach
- D1/D7 der Event-Kohorte
- Spielzeit pro Sitzung
- Umsatz pro Spieler
- Social: Einladungen, Handel
- Qualität: Bug-Reports, Bewertungen
